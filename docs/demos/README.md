改变控制器或重放成功策略。全部使用 Mac 上的 MuJoCo / Robosuite Panda、RGB-D 和 H1 off。

三次独立任务验证均 passed，Agent 均主动取得停止 ACK 并释放租约。
这些是精选成功记录，不能据此计算总体成功率；不同模型、日期和预算也不能作配对比较。
它们不是官方 RoboWorld / CaP-X 评测，也不代表真实机械臂验收。

## 文件与可复查性

- [results.json](results.json)：控制到位、独立任务结果、自主收尾、耗时和已知错误摘要。
- [manifest.json](manifest.json)：原始视频、策略、任务文件的 SHA-256，以及相对于实验 outputs 的来源路径。
- [source-versions.json](source-versions.json)：实验时记录的源码哈希及版本信息。
- 每个任务的 `recording.mp4` 是原始录像的逐字节副本，没有剪掉失败动作。
- `preview.gif` 是同一录像转成的 10 fps 动图，保留全部动作时段和原始仿真播放速度。
  录像不包含模型等待，不能把 6.65 / 6.80 / 16.65 秒的播放时长当作真实任务耗时。
- `policy-*.py.txt` 是模型提交给 `robo_run_policy` 的原始源码，未人工修正或格式化。
  使用 `.txt` 后缀保存历史快照，避免被项目格式化器修改；它依赖受限策略运行时，不是独立 Python 脚本。
- `task.txt` 保留当时给 CLI 的完整自然语言任务。历史预算说明仅用于溯源，不会改变当前配置。

完整模型上下文、工具事件和逐周期轨迹仍保存在原实验工作区，不随这份展示包发布。
本目录发布的是精选录像、原始策略和验证摘要，不是完整会话日志。
实验时源码含未提交修改，因此仅凭当时的 Git HEAD 无法还原精确运行版本；以记录的源码哈希为补充。

## 三条记录分别证明了什么

**Lift 911**：一段策略从点云估计抓取目标，执行接近、下降、闭爪和抬升。
3/3 位置运动到位，独立 `lift_object` 验证通过：物体被抓住且离桌面至少 4 cm。
模型请求 10 次，耗时 129.82 秒。原三场景实验为 3/3，但本页只展示其中 seed 911。

**Stack 1202**：模型先生成抓取策略，再根据反馈生成叠放策略。
6/6 位置运动到位，独立 `stack_objects` 验证通过，稳定窗口为 23 个周期。
曾因并发提出 connect / acquire 得到 `not_connected`，Agent 自主重新申请租约后继续。
源码中的数值目标是该次模型的输出，不是可直接迁移到其他初态的通用策略。
模型请求 10 次，耗时 91.42 秒。

**PickPlaceCan 1302**：模型根据相机点云抓取红罐，再移到 `task_goal` 指定格子。
这是原生单罐任务，目标来自公开固定工位规格，并未证明视觉定位未知目标箱。
第一次策略含 AST 不允许的列表推导式，在动作执行前被拒绝；
[该策略也保留在这里](pickplace/rejected-policy.py.txt)。模型随后生成普通循环版本并成功。
此外曾出现连接前申请租约的 `not_connected`，由 Agent 自主纠正。
7/7 位置运动到位，独立 `place_object` 验证通过：正确格子、松爪、撤离，
连续 20 周期位置漂移不超过 2 mm、旋转漂移不超过 2°。
模型请求 10 次，耗时 106.20 秒。

Lift / Stack 录像属于历史有界协议；PickPlace 属于连续模式，无整任务请求、耗时、动作、
控制周期或每策略语句/循环额度。单次移动仍有收敛判定参数，生成完整性检查、AST 白名单、
取消、停止 ACK 和独立验证均保留。这些历史协议不会由 README 自动应用到用户配置。

连接、武装、策略外验证、停止、释放分别是 CLI 工具调用，未包含在 policy 源码中。
兜底收尾是独立机制，本页的“自主成功”要求 Agent 自己完成上述步骤。
