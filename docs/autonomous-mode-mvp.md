# 自主 Coding Agent 模式（MVP 首版）：实现与边界

> MVP 首版汇总此前探索成果：从零创建网站、大文件写入、分批生成、服务重试、近期上下文、编辑后诊断、动态工具、有界辅助脚本、MiniMax 精确编辑适配、无进展保护、自动续批次和多游戏运行时冒烟。自主循环与安全边界以本文为准；历史试跑文档仍保留当时版本号作为事实记录。

## 1. 方向对应关系

本功能对应原规划中的：

- `2.3 Agent 能力`：Loop、Workflow；
- `2.4 Tool 设计`：文件系统操作、脚本工具、Tool 调用逻辑；
- `2.5 评估体系建设`：智能体能力、工具能力和失败归因；
- 能力场景：VibeCoding。

对应 Claude Code/OpenCode 的核心 Agent Loop：用户给出代码任务，模型读取项目、修改文件、执行验证、根据结果继续修复。v0.2 不是复刻其完整 CLI、Git、权限系统或插件生态，而是抽出最小、可评估的自主闭环。

## 2. 算法意见如何落地

算法意见可拆成三项产品要求：

| 算法意见 | v0.2 落地 |
| --- | --- |
| 给定任务，完成后才能停止 | Harness 不接受文本自报完成；只有代码有变化且最后一次固定验证返回 0 才成功 |
| 中间过程不干预，由模型决策 | 自主模式从 `executing` 开始，不进入计划审批；读取、计划、修改、验证、修复连续运行 |
| 缺少工具时可搜索或自己写 | 新增辅助脚本创建和运行工具；模型可编写 Python 分析工具，结果回到上下文 |
| 工程代码也可开放修改 | 隔离副本中除不可变边界外的可见工程文件均可修改，包括 Harness 源码 |

“必须完成才能停止”不是无限执行。任务仍可能被用户停止、预算终止、模型报告阻塞或系统错误终止；这些状态都不会被记为成功。

## 3. 单次任务流程

```text
用户提交源项目和任务
        ↓
Harness 校验配置并创建隔离副本
        ↓
模型自主读取 / 搜索 / 可选记录计划
        ↓
模型修改代码，或创建受限辅助脚本进行分析
        ↓
执行项目 Owner 固定的验证命令
        ↓
  失败且有预算 ──→ 错误回传模型，继续修改
        ↓
代码有变化且最新验证通过
        ↓
输出隔离副本路径、Diff、验证结果和 Trace
```

源项目不会被自动覆盖。MVP 的输出是一个已验证的候选副本，供实验评估或人工采用。

## 4. 模型可用工具

自主模式的工具全集为 11 个 Tool Schema；每轮只传入当前阶段、预算和模型适配实际允许的子集：

| 工具 | 用途 | 是否改变工程 |
| --- | --- | --- |
| `list_files` | 列出项目文件 | 否 |
| `search_code` | 搜索项目文本 | 否 |
| `read_file` | 分段读取文件 | 否 |
| `submit_plan` | 可选记录计划，调用后自动继续 | 否 |
| `apply_patch` | 对工程文件做局部 Unified Diff 修改 | 是 |
| `edit_file` | 用唯一匹配的 `old_string` 精确替换；MiniMax 默认使用 | 是 |
| `write_file` | 创建、完整重写或分段追加 UTF-8 工程文件 | 是 |
| `write_helper_script` | 创建临时 Python 分析工具 | 否，脚本存放在 Task 运行目录 |
| `run_helper_script` | 运行临时分析工具 | 否，只返回输出 |
| `run_validation` | 执行固定成功标准 | 测试只能写独立临时目录 |
| `report_blocked` | 明确报告无法继续及建议 | 否 |

辅助脚本不是新的无限权限 Shell。模型若要把分析结果转成工程变化，仍必须调用 `edit_file`、`apply_patch` 或 `write_file`，因此变化都会经过同一权限校验，并进入 Snapshot、Diff 和撤销链路。

## 5. 不可变边界

以下边界不交给当前 Run 的模型决策：

1. 源项目：自主任务仅修改临时副本；
2. 成功标准：验证命令、超时和测试/评估配置只读；
3. 敏感路径：`.git`、`.env`、`.venv` 及项目配置的敏感目录不复制、不展示；
4. 当前执行器：模型可改副本中的 Harness 源码，但改动不会接管正在运行的 Orchestrator；
5. 预算：已有项目每批 20 Turn / 15 分钟，任务总上限 60 Turn / 30 分钟 / 80 万 Token，每批最多 10 次辅助脚本运行；建站任务使用 40/120 Turn 的分批/总上限；
6. 网络：辅助脚本和自主验证不能联网；
7. 进程：辅助脚本不能启动子进程；自主验证只能启动预配置的验证可执行文件；
8. 写入：辅助脚本不能写工程；验证只能写 Task 专用临时目录。

这些边界由程序和 macOS 沙箱执行，不仅依赖 Prompt。

## 6. 状态与判定

| 最终状态 | 含义 | 是否通过 |
| --- | --- | --- |
| `success` | 有代码变更，且最新验证 exit code 为 0 | 是 |
| `cancelled` | 用户主动停止 | 否 |
| `budget_exhausted` | Turn 或主动执行时间耗尽 | 否 |
| `failed` | 模型、工具、环境或 Harness 发生错误 | 否 |
| `reverted` | 用户撤销候选副本中的变更 | 否 |

模型输出普通文字、没有代码变化但测试原本通过、或修改后未重新验证，都不能进入 `success`。

## 7. 代码模块

| 模块 | v0.2 职责 |
| --- | --- |
| `orchestrator.py` | 模式选择、自主循环、预算、成功判定和 Trace |
| `workspace.py` | 创建隔离副本并过滤敏感/生成文件 |
| `config.py` | 自主模式写范围及测试/配置保护 |
| `helper_scripts.py` | 临时脚本保存、资源限制和沙箱执行 |
| `validation.py` | 固定命令、超时、独立临时目录和沙箱执行 |
| `tools.py` | 11 个 Schema、参数校验和工具路由 |
| `prompts.py` | 自主模式 System Prompt 与动态 Policy |
| `snapshot.py` | 任务前快照、Diff 和撤销 |
| `trace.py` | 模型/工具/状态/验证事件脱敏记录 |

## 8. 当前验证

v0.2 自动化覆盖：

- 自主模式跳过审批并完成 E01；
- 源项目字节不变，隔离副本发生修改；
- 模型可以创建、运行辅助脚本，再修改和验证；
- 辅助脚本不能写工程、读敏感文件、联网或启动子进程；
- 自主验证可以运行 pytest，但不能写工程；
- 验证原本通过但无代码变化时不能误判成功；
- v0.1 审批、停止、继续、撤销、预算和 Trace 基线未回归。

正式提交算法前仍需用目标模型在同一任务集运行，区分模型行为与 Harness 行为。

## 9. 已知风险与后续项

| 风险 | MVP 处理 | 后续方向 |
| --- | --- | --- |
| 模型无限循环或高成本 | Turn、时间、辅助脚本次数上限 | Token/费用预算和动态熔断 |
| 自写脚本越权 | macOS 沙箱，禁止写入/网络/子进程 | 容器或轻量虚拟机 |
| 测试代码包含副作用 | 验证沙箱和临时目录 | 语言级 Runner、容器快照 |
| 通过测试但代码质量差 | 展示 Diff，保留人工评审 | 静态检查、隐藏测试、Reviewer 模型 |
| 改了 Harness 后自我放权 | 当前 Run 策略在外部进程中保持不变 | 双进程控制面/执行面签名 |
| 只支持既有 Python 运行时 | 不允许在线安装依赖 | 受控工具仓库和依赖白名单 |
| macOS 沙箱可移植性有限 | 非 macOS 自主模式失败关闭 | Docker/Firecracker 等跨平台隔离 |

本期不做自动合并回源项目、Git 提交、任意 Shell、在线搜索/安装工具、MCP/Skill 市场、IDE/终端产品化和 目标平台接入。
