## 3. 固定验证失败

首次 pytest 结果为 5 通过、2 失败：

1. 一段俄罗斯方块注释包含“占位”，触发禁止占位规则；模型随后已删除该词。
2. 当前任务创建于 v0.3.3，受保护验收只识别 `registerGame("literal-id", ...)`，而 20 款游戏均采用语义等价的 `registerGame(game.id, ...)`。v0.3.4 新任务已兼容两种写法，但旧任务验收不会中途变更。

模型在验证后提交了修复 Patch，但随后达到第 40 Turn，尚未重新验证。

## 4. 新发现的真实质量问题

独立执行 `node --check app.js` 后发现 JavaScript 语法错误：记忆翻牌模块边界包含字面量 `\n`，不是换行符。旧固定验收只检查字符串、清单和关键代码信号，没有解析 JavaScript，因此未直接报告该问题。

这意味着即使只修复上述两个 pytest 断言，页面仍可能无法运行。不能把“字符串验收通过”当作可玩网站完成。

## 5. 归因

| 层级 | 结论 |
|---|---|
| 模型 | JavaScript 语法错误及部分低质量实现的直接来源 |
| Harness | 缺少编辑后语法诊断和最终 JS 解析门槛，反馈过晚；旧任务验收不兼容变量 ID |
| 环境 | Node.js 可用，能够稳定复现语法错误，不是环境故障 |
| 评估 | 已首次进入固定验证，但尚未通过，也未进入人工逐游戏试玩 |
| 预算 | 在验证后修复阶段正常止损，不应简单放大预算 |

## 6. OpenCode 对标与 v0.3.5 调整

OpenCode 会在编辑后把 LSP 诊断返回模型，而不是只依赖任务末尾的测试。参考其维护者对编辑诊断机制的[官方说明](https://github.com/anomalyco/opencode/issues/711#issuecomment-3044408738)和[工具注册源码](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/tool/registry.ts)。

MVP 不引入完整 LSP，只实现当前场景需要的最小等价能力：

1. 每次 `write_file` 或 `apply_patch` 修改 `.js` 后，使用 `node --check` 只解析、不执行代码，并把诊断随工具结果返回模型。
2. 静态网站的 `run_validation` 先执行同一语法检查；语法不通过时不能成功。
3. Prompt 和受保护任务说明要求模型先处理 `syntax_check(s).passed=false`，再继续功能。
4. Trace 将单 Run Token 与 Task 累计 Token 分开记录。
