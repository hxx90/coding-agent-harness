# 开发记录

日期：2026-09-15。基线：`e2a2ca0`。

## 架构决定

原项目是 Streamlit 实验台，核心流程集中在 `TaskOrchestrator`，工作方式是复制项目、执行一个固定任务并验收。持续使用的 CLI 需要在已有工程中多轮协作、恢复、授权和撤销，不能只给旧 Orchestrator 包一层命令行。

因此新增 `coding/` 包。终端只负责输入输出，`CodingSession` 负责循环和状态，Provider 负责网络，ToolSet 统一执行与权限，Workspace 管理真实文件。保留旧网页引擎和原有验收语义；Streamlit 移到可选依赖。

交互形态采用简单 REPL 与斜杠命令，提供 `run` 和 JSONL 供自动化调用。没有引入服务端、全屏终端渲染或数据库。

## 实施过程

2. 配置、权限、持久化和工作区先行，针对真实临时文件验证读后编辑、外部冲突、快照和子进程。
3. 实现 HTTP/SSE Provider 与会话引擎，接通真实 HTTP 的读、改、测试、修复闭环。
4. 加入 REPL、JSONL、会话管理、附件和上下文；按调用前/结果后的持久化顺序处理进程崩溃。
5. 加入本地 Skills、受限探索子会话、真实 MCP stdio 初始化与工具调用。
6. 通过真实 PTY 验证确认操作、连续两轮、模式切换、Ctrl+C 取消模型/Shell 后恢复。
7. 修复旧版 macOS 沙箱回归，执行全量测试和构建；在独立环境确认 CLI 不依赖 Streamlit。
8. 完成架构、手册、验收矩阵和两轴代码审查，审查结果另记。

## 测试推动的修复

| 发现 | 修复与证据 |
| --- | --- |
| Shell 父进程退出后，后代仍持有 stdout 管道，任务一直不结束 | 超时/取消时清理整个 POSIX 进程组，即使父进程已退出；有真实 fork 子进程测试 |
| 同步 HTTP 线程关闭响应不能可靠取消等待 HTTP 头 | 改为 async HTTPX 任务，取消 coroutine；头与体阶段均在实测期限内退出 |
| SSE 可能将凭据切成多个 chunk | 缓冲可能的已知凭据前缀，完整匹配后遮盖；事件、会话和导出覆盖测试 |
| 仅以全量 Git 可见文件做快照会漏掉被明确编辑的忽略文件原内容 | 在首次文件修改前保存该文件原始快照并持久化额外路径；跨实例撤销测试 |
| 工具调用中断后，继续会话可能留下无结果的调用 | 将未确认调用补为 interrupted_operation，要求重新查看当前状态，不自动重放 |
| 项目锁失败被会话锁的异常处理误报为 session_busy | 只在获取会话锁的位置捕获 Timeout，项目执行锁错误独立报告 |
| Diff 对空文件、仅权限变化、无末尾换行不清楚 | 补充文件与权限位信息、无换行标记，并测试 CRLF 保留 |
| Homebrew Python 实际启动链超出旧沙箱白名单 | 增加 Framework 真实解释器的精确执行规则与 Python 安装目录元数据权限。原 10 项失败全部修复，原有写入/敏感读取/联网/其他程序执行限制继续通过测试 |

## 首次全绿后的审查修复

两路审查在 163 项通过后仍找到了权限路径别名、外部编辑归属、授权取消、结构化状态脱敏和关闭输出后的命令等待问题。这些问题均先有最小复现，再修复并加入集中回归；两位审查 Agent 已独立复核通过，详见 06 文档。

为解决外部编辑归属，新增 ChangeJournal。它只记录实际工具执行，文件工具只记录其触及的文件，不再以整轮开始/结束之间的全项目差异充当 Agent 修改。同时对未确认归属的崩溃中变更拒绝自动撤销。

另补齐损坏的 turns/redo/active/extra_paths 检查、MCP env 类型检查和 session 文件大小上限；保留最后一份可用的持久化状态。Shell 与 MCP 的环境过滤使用同一实现。

最终验收：全部 **184 项测试通过**（22.30 秒），类型检查覆盖 15 个源文件，24 个文件静态/格式检查通过。最终 wheel 独立安装与三次 HTTP 请求的实际编码/验证冒烟通过。

## 2026-09-16 Provider 兼容修复

本地首次接入真实网关时先出现 HTTP 405。诊断确认 CLI 会在 `base_url` 后拼接 `/chat/completions`，而本机配置误用了站点根地址；将 `AGENT_HARNESS_BASE_URL` 改为带 `/v1` 的 API 根路径后，模型列表端点恢复正常。

随后 `gpt-5.6-sol` 明确拒绝 `max_tokens` 并要求 `max_completion_tokens`。为保留其他 OpenAI-compatible 服务的兼容性，Provider 没有全局替换字段或按模型前缀猜测，而是解析结构化 400 错误，只对明确的 `unsupported_parameter` 响应做一次参数切换；成功后在 Provider 实例中记住协商结果，避免每个 Agent 回合重复 400。测试覆盖首次请求、兼容重试和下一次 completion，并保留原有限重试语义。

修复后真实模型最小任务成功完成；相关测试、Ruff、Mypy、全量 218 项测试和 Diff 检查均通过。
