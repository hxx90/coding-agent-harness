# 目标与验收要求

日期：2026-09-15。

用户原始目标：

> 请你参考 opencode 代码，给我设计成一个简洁但包含完整功能的 coding agent cli，注意需要做完整的测试和文档记录到目录的 ./devlog 下。

## 产品形态

独立的 `agent-harness` 命令。默认进入支持连续对话的交互终端，同时提供单次运行、标准输入和 JSONL 事件输出，方便脚本与其他工具集成。界面保持简洁，核心能力通过普通命令和斜杠命令访问。

不要求用户先启动网页、创建测试配置或安装 Streamlit。已有网页作为可选入口继续可用。CLI 在任意已有目录或空目录都能工作。

## 模块接口与测试策略

主要测试面是用户使用的命令行、可恢复的 CodingSession、Workspace 操作和 Provider 的 HTTP 协议。优先使用临时真实文件、真实子进程与本地 HTTP/MCP 服务。测试适配器只替代外部模型，不能替代待验证的工具和会话实现。

按能独立跑通的功能逐步实现并测试：

1. 固定 OpenCode 参考版本，记录架构取舍与已有测试基线。
2. 配置、权限、工作区和会话持久化。
3. 模型协议与 Agent 循环，跑通单次真实 HTTP 工具任务。
4. 交互终端、恢复、撤销、附件与上下文管理。
5. Skills、探索子任务与 MCP 扩展。
6. 异常路径、取消与并发；处理旧版回归问题。
7. 完整测试、安装验证、PTY 验收、代码评审与文档核对。

## 已知基线

初始工作树干净，项目版本 1.0.0，入口为 Streamlit。此前本机 Python 3.11.10 测试 57 项通过、10 项失败；失败集中于 macOS 沙箱的 Python 启动路径和路径元数据权限。新 CLI 的跨平台权限与命令执行需要独立实现；旧版沙箱问题也需要回归处理，不能通过跳过失败测试声明完成。

没有已配置的真实模型密钥。确定性验收使用本机模型协议服务，真实模型验收作为独立步骤记录，不能把 Demo 或协议服务的结果称作真实模型能力验证。
